# 项目会话交接

阅读项目根目录 `AGENTS.md`、已有 `交接.md`，以及本次会话的实际操作记录。先检查当前分支、`git status --short --branch`、最近提交及远程配置，区分本次变动与用户原有工作。

更新根目录 `交接.md`：

- 顶部维护当前状态、关键业务决策、重要文件、验证命令和接手后的第一步。
- 在会话记录中追加本次日期、完成事项及主要步骤、实际验证结果、已知限制和剩余任务；同一会话重复结束时合并该条，避免重复堆积。
- 只记录事实。明确区分“设计建议”“已实现”“已测试”“已推送”“已上线”；未做的事不能写成完成。
- 保留仍有效的历史决策和未完成事项，删除或改正已经失效的当前状态。不要复制整段聊天或冗长命令输出。
- 可记录已经存在的相关 commit；本次交接提交尚未生成时写“见 `git log -1`”，不要猜测哈希，也不为补写该哈希反复提交。
- 不写入密钥、客户图纸、客户隐私或未经授权公开的资料。项目外变动可记录路径和摘要，不复制本机配置到仓库。

为本次文档变动补充或更新适用验证。运行 `python -m unittest discover -s tests -v` 和项目约定的其他检查，确认通过后审查差异，只暂存本次任务文件并创建 Git commit。检查提交后的工作区，向用户报告交接文件路径、验证结果、提交号及未完成事项。

“此对话结束”只授权整理与提交交接，不自动授权推送、部署、归档聊天、清理文件或更新全局记忆。若本次会话已另有明确推送或部署授权，按该授权及项目规则处理。
